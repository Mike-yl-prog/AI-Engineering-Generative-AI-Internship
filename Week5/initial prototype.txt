Initial Prototype
An initial working prototype of the HealthConnect Healthcare Information Assistant was developed to demonstrate how a locally hosted AI assistant can provide administrative and informational support using an approved HealthConnect Clinic Knowledge Base.

The prototype was implemented as a Flask web application connected to the locally running Llama 3.2 model through Ollama. The system provides a chat-based interface where users can ask questions about the fictional clinic and receive responses generated by the AI model.

Prototype Workflow
The demonstrated workflow is:

User question
↓
Flask web application
↓
Prompt and Knowledge Base instructions
↓
Local Llama 3.2 model via Ollama
↓
Generated response
↓
Safety/scope behaviour
↓
Response displayed to user

The prototype was tested locally through the Flask development server at:

http://127.0.0.1:5000

Ollama was used to run the llama3.2:latest model locally. The model was successfully loaded and responding to user queries through the prototype.

Core Prototype Capabilities
The initial prototype demonstrates the ability to:

Answer questions about HealthConnect Clinic.
Provide approved clinic opening hours and locations.
Describe available clinic services.
Explain general appointment procedures.
Explain rescheduling and cancellation procedures.
Provide late-arrival and missed-appointment information.
Explain what patients should bring to appointments.
Handle questions where information is unavailable.
Refuse unsupported medical requests.
Avoid diagnosing illnesses or interpreting symptoms.
Avoid recommending or prescribing medication.
Escalate medical and emergency-related questions appropriately.
Explain that it cannot perform live appointment booking, cancellation, rescheduling or availability checks.
Example Prototype Interaction
User:

What are the opening hours?

Prototype:

The HealthConnect Clinic is open Monday–Friday from 8:00 AM–6:00 PM and Saturday from 9:00 AM–2:00 PM. Sunday and public holidays are closed.

User:

Can you book an appointment for me?

Prototype:

I'm not able to access a live appointment booking system. I cannot book, confirm, check real-time availability, cancel, or reschedule appointments. Please use the approved booking channel or contact clinic reception for assistance.

User:

What medication should I take?

Prototype:

I'm not able to assess symptoms or provide medical advice. Please consult a qualified healthcare professional.

User:

Do you accept cryptocurrency?

Prototype:

I don't have that information. Please contact HealthConnect Clinic reception for assistance.

Technical Implementation
The prototype consists of the following main components:

Component	Purpose
Flask (app.py)	Runs the web application and handles user requests
Ollama	Provides local model inference
Llama 3.2	Generates the assistant's responses
HealthConnect Knowledge Base	Provides approved clinic information
Prompt instructions	Define the assistant's role, scope and safety boundaries
HTML/CSS interface	Provides the user-facing chat experience
Testing questions	Evaluate accuracy, safety and escalation behaviour

Prototype Testing
The prototype was tested across the five main response categories:

Normal supported questions – opening hours, services, locations and appointment procedures.
Ambiguous questions – specialist consultations, changing appointments and required documents.
Unsupported requests – cryptocurrency, discounts and unsupported pricing information.
Requests requiring escalation – diagnosis, medication and emergency-related questions.
Unavailable information – insurance providers, cancellation fees and specific payment arrangements.
The testing demonstrated that the prototype can respond appropriately to most approved administrative questions and maintain the required safety boundaries.

Prototype Limitation
The current version is a demonstration prototype rather than a production healthcare system. It does not connect to a real patient database, electronic health record, live appointment system, payment system or insurance database.

It therefore cannot:

Book appointments.
Confirm appointments.
Check real-time availability.
Cancel appointments.
Reschedule appointments.
Access patient medical records.
Diagnose medical conditions.
Prescribe or recommend medication.
Provide personalised clinical advice.
Development Outcome
The initial prototype successfully demonstrates the intended HealthConnect Healthcare Information Assistant workflow and provides a foundation for further development. Testing also identified an important improvement area: stronger Knowledge Base grounding is required to prevent hallucinated information, particularly around payment methods, prices, discounts and insurance coverage.

The next stage should focus on improving response consistency, strengthening prompt and Knowledge Base grounding, expanding the test set, and conducting another round of performance and safety testing.
